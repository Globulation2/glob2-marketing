[Repository overview](../README.md) · [Task ledger](../planning/tasks.md) · [Analysis](../analysis/README.md)

This section inventories what already exists and reconstructs the game's history. Records must cite dated sources and distinguish current evidence, historical evidence, and unverified leads. Account ownership, rights, active maintenance, and live availability require separate verification.

## Ledgers

- [Repositories and web properties](repositories.md): source locations, revisions, public properties and implementation boundaries.
- [Marketing assets](assets.md): logos, screenshot families, video, copy, provenance and gaps.
- [Product and commercial capabilities](product.md): gameplay, creator systems, payment machinery and measurement limits.

- [Communication channels](channels.md): current public surfaces, legacy community destinations and independent visibility.
- [Distribution platforms](distribution.md): observed releases/listings, preparation-only stores and version/context differences.
- [History](history.md): predecessor, development, releases, community and hosting milestones, with chronology gaps.

The first bounded inventory pass is complete. Open verification work remains within each ledger; completeness of this pass does not establish an exhaustive estate audit.

## Scope and evidence limits

The initial pass covers available local source repositories and publicly accessible evidence. It is not an exhaustive audit of private accounts, analytics, paid platform dashboards, unpublished plans, ownership, or permissions. Access-restricted leads are omitted or described only at a non-sensitive level. Source code shows implementation at the cited revision or observation date; it does not establish production deployment, active users, revenue, or a functioning live service. Record those separately when verified.
