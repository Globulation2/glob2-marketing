# AI and developer media for Glob2

[Outreach project](README.md) · [Product and prior art](product-and-prior-art.md)

Research checked **2026-11-23**. This lane covers AI and technology reporters, hands-on developer publications, newsletters and podcasts. The order reflects demonstrated editorial fit and the evidence a recipient would need. It makes no claim about interest, reply rates or audience size. Public routes are supplied for future use and have not been tested by sending. Check for overlap with the game's other outreach before using a shared desk.

The most useful local story is an existing open-source colony RTS with two things a coding agent can do. First, connect to the actual desktop application through its built-in Model Context Protocol server and operate its UI. Second, help a player write and revise a JavaScript strategy for the game to run. Show the two mechanisms separately and explain which one is on screen. The public Hive Mind guide still describes its online experience as coming soon, and MCP-only matchmaking has merged in the game repository but was absent from the latest checked desktop release and the publicly listed queues. Any demonstration of assisted play against a human online is a separate milestone and needs a consented match on the supported build and instance. [Desktop MCP guide](https://github.com/Globulation2/glob2/blob/master/docs/development/mcp-ui-server.md) · [Public Hive Mind guide](https://glob2.online/learn/hive-mind/) · [Hive Mind engineering notes](https://github.com/Globulation2/glob2/blob/master/docs/multiplayer/hive-mind.md) · [MCP-only queues implementation](https://github.com/Globulation2/glob2/pull/1897)

## Ecosystem and community placements

These are separate from independent coverage. Confirm current rules when a placement is authorized.

- **Show HN.** A working download or code path readers can actually try fits the [Show HN rules](https://news.ycombinator.com/showhn.html). The maker of [Castellan](https://news.ycombinator.com/item?id=50246334) already showed an agent-oriented RTS there. Its [repository](https://github.com/emersoftware/castellan) describes an MCP server, local matches and a public replay viewer. That precedent makes category claims particularly fragile. A Glob2 post would earn attention through a readily reproducible, human-directed experiment and maintainers available for technical questions.
- **MCP Registry.** The [official registry](https://registry.modelcontextprotocol.io/) and [publication documentation](https://github.com/modelcontextprotocol/registry/blob/main/docs/modelcontextprotocol-io/quickstart.mdx) are metadata and discoverability channels. Check current official publication requirements and applicability to a bundled desktop loopback server or optional stdio bridge. A listing does not imply endorsement, testing or coverage.
- **AI Engineer events.** [AI Engineer's program](https://ai.engineer/) has talks, workshops and demos. The [Nov. 2026 Code Summit](https://ai.engineer/code/2026/talks) already passed. Look for a future open technical call and an engineering lesson that applies beyond the game. Latent Space and AI Engineer have overlapping organizers, so route a coordinated approach.
- **GitHub Blog / ecosystem amplification.** The [GitHub Blog publishes practical MCP examples](https://github.blog/ai-and-ml/github-copilot/building-your-first-mcp-server-how-to-extend-ai-tools-with-custom-capabilities/) and [maintainer stories](https://github.blog/open-source/maintainers/welcome-to-maintainer-month-celebrating-the-people-behind-the-code/). A vendor-authored example would need a verified run on the relevant client and a real maintainer story. An open editorial submission route was not confirmed.
- **The Rundown AI.** [News About](https://www.therundown.ai/news/about) provides a correction/editorial question address. A suitable intake for standalone tool pitches was not verified. Its [workflow community](https://app.therundown.ai/community) is a different channel. Hold until a route and a concise copyable workflow are available.

## What to provide for each story

| Format | Bring | Good lead examples |
| --- | --- | --- |
| Hands-on play | A native build and exact OS/client, the real MCP setting, one playable map, the precise prompt that generated the policy, a downloadable example, and a reproducible human-observable outcome. Show the model's output and action taken. Record launch-to-play time and setup cost when measured. | Simon Willison, TechRadar, Ben's Bites, Changelog News |
| Engineering case study | Explain desktop UI actions vs. controlled local gameplay vs. JavaScript execution. Give a small trace, architecture diagram or task walkthrough, plus failure cases and an account of what happens when the agent is too slow. | Latent Space, The Pragmatic Engineer, The New Stack, VentureBeat, heise |
| Reported test or exhibition | A replay and a real participant who can describe the match. Provide versions, rules, what help each side got, room/queue policy, and what happened when the strategy failed. A staged private exhibition should say so. Any public ladder story needs independent reproduction on the supported release and live instance. | Ars Technica, TechCrunch, GamesBeat, Tom's Hardware, Axios, TIME, WIRED |
| Experimental report | Freeze map seeds, model versions, time budgets, process for revisions and completion criteria. Release the traces or replays, note human intervention, and avoid general model rankings from one scenario. | Import AI, Latent Space, Tom's Hardware |

Two firsthand comparisons are worth linking in reporter background. The [PokéAgent Challenge paper](https://arxiv.org/abs/2603.15563) documents MCP-based gameplay in a circa-2025 research system. Willison's *Battle Drones* and [The Interface maker's account](https://news.ycombinator.com/item?id=44943986) show how closely experiments already overlap with vibe-coded strategy, real-time human/agent interaction and online play. Differentiation comes from the specific workflow the team can show and readers can repeat.
